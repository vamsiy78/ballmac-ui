# Pro phases 6 and 7: Beacon SaaS starter and Figma kit sources

Written 2026-10-03. Nothing here copies code from another starter or kit: the pieces are Better Auth, Drizzle, Stripe's official SDK, React Email and Resend (all MIT or Apache-2.0 libraries used through their public APIs) plus Ballmac UI itself.

## What a SaaS starter has to get right

Starters usually fail in the same places, so those are where the effort went:

1. **Auth checked in one place only.** A cookie check in a proxy or middleware is a convenience, not security. Here the proxy only redirects; every page, layout and server action calls `requireSession`, `requireWorkspace` or `requireAdmin`. `AGENTS.md` and the README say so, because the next person to add a page will copy what they see.
2. **Tenant isolation.** Every workspace query filters by `organization_id`, including deletes and revokes (`WHERE id = ? AND organization_id = ?`). Tests prove one workspace cannot delete another's project or revoke another's key.
3. **Billing state only from Stripe.** Plans change only in the verified webhook. Events are stored so a retry is applied once, and the record is removed when handling fails so the retry is processed. `past_due` keeps access while Stripe retries the card; unpaid and canceled fall back to the free plan.
4. **Limits as one function.** Plan limits are read in `entitlements.ts` and used by the UI, the server actions, the public API and the invitation flow. Seats count open invitations, so ten pending invites cannot exceed the plan.
5. **Runs with nothing installed.** Development uses PGlite (Postgres in WebAssembly), so `pnpm install && pnpm dev` works without Docker. Production requires `DATABASE_URL`; the embedded database in production needs an explicit flag.
6. **Email that cannot silently vanish.** Without a Resend key, development prints emails and tests read them; production refuses to run without one, so password resets and invitations never disappear.
7. **No invented claims.** Home page copy is placeholder and says so; no fake customer counts or ratings. Legal pages are placeholders that explain why they are empty. Plan prices are sample numbers in `src/config/plans.ts`.

## Decisions

- **Workspaces are Better Auth organizations**, not a custom table: roles, invitations, membership limits and active-workspace sessions come with it. Billing hangs off the organization.
- **Stripe, behind a small interface** (`StripeLike`). The webhook, checkout and portal logic is tested with a fake, and replacing the provider means replacing `billing.ts` and `stripe.ts` only. The owner of this repository sells Pro through another provider; customers of the starter choose their own.
- **Migrations are SQL files** generated by drizzle-kit and applied by the app in development and by `pnpm db:migrate` in production.
- **Better Auth's own rate limit stays on** (and is documented as per instance); e2e tests switch it off only when no real database is configured.
- **UI is vendored, not linked.** `pnpm starter:vendor` copies the Ballmac items (and everything they depend on) into the starter from the built registries, so the starter is a plain app the customer owns. It adds the npm packages those items need to `package.json` and records what it copied.
- **Delivery through the licence key.** Starters are packed into the private build and served from `/r/pro/starters/<name>.tar.gz` with the same bearer key as the registry (same gate, rate limit and no-store headers).

## What testing found

Everything below was found by running the app, not by reading it:

- Better Auth's `membershipLimit` applies when an invitation is accepted, not when it is sent, so the app checks seats before inviting.
- Better Auth rate-limits sign-in and sign-up (about three a ten-second window), which broke fast test sign-ups: now configurable and off only for tests.
- Pages that read headers must do so before opening the database, or `next build` tries to render them and needs secrets. `getSession` reads headers first.
- A duplicate workspace name returned `ORGANIZATION_ALREADY_EXISTS`, which the first retry rule missed; and the error class from Better Auth can come from a second copy of the package, so errors are recognised by shape.
- `Field` does not wire its controls by itself, so labels were not attached to inputs. Small wrappers (`FieldInput` and friends) fix it everywhere.
- Pro blocks could not hide optional parts because default parameters replaced `undefined`: header-pro-2's announcement, team-pro-1's join card, newsletter-pro-1's readers line and hero-pro-14's ticket bar now take `null`; hero-pro-1 hides its pill and proof row when empty; onboarding-pro-4's skip button only shows when `onSkip` is given. A prop type in auth-pro-5 collided with the DOM `onReset` handler.
- A reveal timing bug in header-pro-1: a hover timer could reopen the menu after a keyboard action.
- Dialog scans need a short settle time (axe measured contrast mid-fade); a modal menu hides the page, so four expected findings are ignored for that one state only.

## Verified

Unit tests (32): database, auth, workspaces, seats, limits, billing with a fake Stripe, projects, API keys, environment, helpers. End-to-end tests against a production build (24): marketing, sign-up to dashboard, sign-out and in, protected redirects and open-redirect safety, wrong password, password reset by email, projects with the free limit, invitation accepted by a second user, API keys end to end, settings, billing without Stripe, workspace switching, axe in light and dark on every page, open dialogs and menus, keyboard skip link, no sideways scroll at 390 px on every page. A fresh copy (install from the lockfile, lint, typecheck, test, build) passes outside the repository (`pnpm starter:pack beacon-saas --verify`).

## Not done

- No live Stripe test: checkout, portal and webhook handling are tested with a fake, and the signature check is exercised only for the "no signature" case. Run through `docs/BILLING.md` with test keys before launch.
- OAuth sign-in (GitHub, Google) is wired but was not exercised against the providers.
- Email was verified through the outbox, not through Resend.
- No right-to-left pass on the starter's own pages (the vendored blocks are RTL-checked in the library).
- Two-factor sign-in and passkeys are not included.
- Team-wide settings such as SSO, audit export and custom roles are not included.

## Figma kit

See `FIGMA-KIT.md`. Tokens: 13 themes as W3C design tokens, checked for contrast after rounding to hex. Captures: PNG and HTML at 1440 and 390 px, light and dark, with a manifest. The Figma component library itself needs a designer and is not built.
