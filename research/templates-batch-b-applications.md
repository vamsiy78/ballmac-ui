# Templates batch B: applications

Reviewed 2026-10-01. Four application templates that install as working routes, not mockups: Atlas (store admin), Muse (AI chat app), Parcel (productivity workspace, `template-workspace`) and Auth Kit (a complete sign-in flow in three layouts). All code is original Ballmac work assembled from components and blocks already in the registry; nothing was copied from Aceternity, Tailwind Plus (Catalyst, Protocol, Syntax), Magic UI Pro, shadcnblocks or any paid kit, so none carry a "Based on" header. They were compared with those kits, [shadcn blocks](https://ui.shadcn.com/blocks) (dashboard, sidebar, authentication), [Origin UI](https://originui.com), [Tremor](https://tremor.so) templates, [21st.dev](https://21st.dev/community/components), and the products themselves: Shopify admin, Linear, Stripe Dashboard, ChatGPT and Claude, Superhuman, Notion Calendar, Clerk and Auth0 hosted pages.

What most template kits do: a screenshot-grade dashboard with no behaviour, one shared look, and a sign-in form that stops at the happy path. What these do instead:

| Template | Look | Signature interaction | Pages | What is better than the usual |
| --- | --- | --- | --- | --- |
| Atlas | Warm stone neutrals with one teal, Manrope and Geist Mono for ids | A real work queue: orders with status tabs and counts, sortable columns, row selection with bulk actions and pagination; an order page with a timeline and a refund flow that validates | Dashboard, Orders, Order detail, Products, Customers, Settings | Everything works over typed sample data: filters, sort with `aria-sort`, bulk ship, refund with item picking, an add-product drawer that focuses the first error, a save bar that appears only when something changed; a ⌘K menu; a drawer on phones |
| Muse | Lilac-tinted paper, plum ink, one coral, DM Sans with Source Serif 4 for replies | A reading-first chat: reasoning disclosure, source pills, a document panel, a model picker, a streamed reply to anything you send | Chat, New chat, Projects, Library, Settings | Replies are set in a book serif at 17 px and 32 px line height; projects have editable instructions and files; settings preview font and size live and gate account deletion behind typing a phrase |
| Parcel | Cool paper, navy ink, one blue, Albert Sans | A Today page that joins the apps: agenda with a now line, tasks you can tick and add, inbox highlights you can archive, a focus timer | Today, Mail, Calendar, Board, Settings | The app rail turns into a tab bar on phones; mail, calendar, board and settings are the Ballmac blocks, so they take your data through props |
| Auth Kit | Soft ivory and ink with one indigo, Outfit | A playground that switches page and layout (centered, split with art, frosted glass) live | Playground, Sign in, Sign up, Verify, Forgot, Reset, Invite, Onboarding | Every state is covered: validation that focuses the first problem, a live password checklist and strength meter, a six-digit code with a resend countdown, mismatch errors, a success state per page |

Shared decisions: each palette is a scoped block of standard Ballmac tokens in a `<style>` string for light and dark. Dialogs, drawers and menus render in a portal outside the template element, so the same variables are also applied through `body:has(.template-theme)` and the font variables are added to `<body>` while a page is mounted; without that, portaled UI would use the host app's colours. Pages take an `hrefs` prop so previews navigate between sibling previews, while installed routes use real paths. Data is fixed and deterministic (no randomness in render, fixed `en-US` formatting, ISO dates in UTC).

Accessibility notes: axe (serious and critical) is clean on every page in light and dark, and `scripts/a11y-open-states.ts` scans interacted states (switched ranges, a selection with the bulk bar, a refund dialog with an error, a profile drawer, the save bar, an open model list, a streamed reply, an open preview, validation errors on every form). Sorting is on real buttons inside `th` with `aria-sort`; filters are `aria-pressed` buttons with a polite result count; scrollable tables are focusable regions; destructive actions ask first.
