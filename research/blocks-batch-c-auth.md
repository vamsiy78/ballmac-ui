# Blocks batch C: authentication and onboarding

Reviewed 2026-10-01. All six blocks are original Ballmac code assembled from components already in the registry (field, input, password input, input OTP, checkbox, select, button, badge, Motion and lucide-react). No code was copied from Aceternity, Tailwind Plus, shadcnblocks or any Pro kit, so none carry a "Based on" header. Patterns were compared with the [shadcn blocks](https://ui.shadcn.com/blocks) login and signup sections, [Origin UI](https://originui.com), [ReUI](https://reui.io), [DaisyUI](https://daisyui.com), [21st.dev](https://21st.dev/community/components) auth sections, and the sign-in, verification, recovery and invitation flows of well-known products.

Shared decisions: validation runs on blur and on submit, focuses the first invalid control and links every message with `aria-describedby`; a failed request is a visible, announced alert that never wipes what the person typed; multi-screen flows move focus to the new heading (callback ref, so it also works behind an exit animation); every async action takes a handler that may throw, and works with a short simulated delay when you pass none, so each state can be tried in the demo; no brand icons (lucide has none), so social sign-in is a generic SSO button and a passkey button; copy is plain and specific.

| Block | Competitor pattern studied | Ballmac improvement |
| --- | --- | --- |
| Login 2 | Split-screen sign-in pages | SSO and passkey, show/hide password with `aria-pressed`, remember me, announced error banner, a picture side that is a soft colour mesh with a floating metric card and a customer quote (or any node via `visual`), hidden below `lg` |
| Signup 1 | Signup with a pitch column | Live strength guide, terms checkbox with its own error, SSO option, benefits and proof column, confirmation screen that tells you where the email went |
| Forgot Password 1 | Single-screen reset forms | The whole recovery flow in one card (request, sent with resend countdown, new password with confirmation, done), usable on both the request page and the page the emailed link opens |
| Verify 1 | OTP entry screens | Masked email, slots that accept typing and pasting, submit on the last digit, shake and alert on a wrong code with the field cleared and refocused, resend cooldown, animated success, any code length |
| Onboarding 1 | Setup wizards | Progress rail on tablets and up, compact bar on phones, workspace address filled from the name until edited, goal cards as real checkboxes, color radios, invitations as removable chips, review, finish; slides between steps |
| Invite 1 | Invitation landing pages | Workspace tile and role, what the role allows, the account being used with "Not you?", accept and decline with real loading and failure states, welcome, declined and expired variants |

Accessibility notes: axe (serious and critical) is clean on every `/preview/*` page in light and dark, and `scripts/a11y-open-states.ts` scans the interacted states (validation errors, wrong password, weak password, the sent screen, mismatched passwords, a wrong and a right code, goal selection, the finish screen, accepted and requested invitations). Findings that shaped the final code: destructive text on a tinted destructive background failed contrast in light mode (error banners are now outlined, with the text on the page background, and this was fixed in the contact form pattern too), and the onboarding heading focus ran before the heading had mounted behind `AnimatePresence`, which the tests caught (focus now happens as the heading mounts).
