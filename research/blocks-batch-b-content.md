# Blocks batch B: content and company pages

Reviewed 2026-10-01. All eight blocks are original Ballmac code assembled from components already in the registry (Radix through `radix-ui`, Motion, lucide-react and our own button, field, input, textarea, select, checkbox, search field, segmented control, breadcrumb, copy button, scroll progress, table of contents and status dot). No code was copied from Aceternity, Tailwind Plus, shadcnblocks or any Pro kit, so none carry a "Based on" header. Layouts and interaction patterns were compared with the [shadcn blocks](https://ui.shadcn.com/blocks), [Magic UI](https://magicui.design), [Origin UI](https://originui.com), [ReUI](https://reui.io), [DaisyUI](https://daisyui.com), [21st.dev](https://21st.dev/community/components) community sections, and the public blog, changelog, careers and 404 pages of well-known products for pacing and hierarchy.

Shared decisions: no stock photos or external images (a generated cover drawn from theme tokens stands in, in five compositions, and `image` takes a real photo); dates are ISO strings formatted in UTC with a fixed locale so server and browser agree; every filter is a set of real buttons with `aria-pressed` plus a polite result count; every form validates on submit, focuses the first invalid field and links errors with `aria-describedby`; every block works as a single column at 390 px and stops motion for reduced motion.

| Block | Competitor pattern studied | Ballmac improvement |
| --- | --- | --- |
| Blog 1 | Featured-plus-grid blog indexes | Generated covers (`BlogCover`, exported) so a demo never needs photos, topic filter with announced count, one link per card (stretched), image zoom that respects reduced motion |
| Blog Post 1 | Long-form article templates | Comfortable prose styled from plain elements (no typography plugin), pull quote and code, scroll-spy contents, reading progress bar, copy-link button, author card, related posts, `children` for your own body |
| Changelog 1 | Release-note timelines | Sticky version and date column, typed changes with text labels (never colour alone), type filters with counts, optional banner art, show-older button, feed link |
| Contact 1 | Contact sections with a form | Real validation with focus on the first error, topic select, character counter, consent checkbox, loading, error and thank-you states, response-time pill, method tiles |
| Careers 1 | Job boards | Roles grouped by team, team chips and live search, empty state with reset, whole-row links, perks grid, open-application line |
| Comparison 1 | "Us versus them" tables | Your column lifted into its own card, yes / partly / no / text cells that read as full sentences to screen readers, headline results, phone layout that compares against one alternative at a time |
| Newsletter 1 | Email capture sections | Topic chips, validation with announced error, loading, error and success states, avatar proof and a tilted sample-issue card that shows what readers receive |
| Error 1 | 404 pages | One component for 404, 403 and 500 with plain-language copy, a zero drawn as a ring with an orbiting moon (stops for reduced motion), numerals hidden from assistive technology behind a prefixed heading, site search, helpful links and a support reference |

Accessibility notes: axe (serious and critical) is clean on every `/preview/*` page in light and dark, and `scripts/a11y-open-states.ts` scans the interacted states (a filtered blog, expanded and filtered changelog, the contact form with errors and after sending, an empty careers search, the compared alternative, the newsletter error and success states, the focused 404 search). Findings that shaped the final code: the 404 glow overflowed 390 px (the section now clips horizontally), avatar initials overlapped each other, and the comparison results printed their label above the number in the wrong source order.
