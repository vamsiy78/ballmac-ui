# Wave 10 batch B: devices and system UI

Reviewed 2026-10-01. All seven items are original Ballmac code built on primitives already in the registry (Radix `Slider` through `radix-ui`, Motion, lucide-react, and the same `cqw` container-unit approach as `phone-frame`). No code was copied from Aceternity, Tailwind Plus, any Pro kit or anything unlicensed, so none carry a "Based on" header. Patterns were compared with the [Magic UI](https://magicui.design/docs/components) iPhone, Safari and Android mockups, [shadcn](https://ui.shadcn.com/docs/components) (slider, toggle, card), [DaisyUI](https://daisyui.com/components/mockup-phone/) mockup-phone and mockup-window, [21st.dev](https://21st.dev/community/components) device frames, and the real behavior of macOS 14/15 (lock screen, Control Center, volume and brightness HUD, desktop widgets), iOS lock screen and Apple Watch, Pixel and iPad Pro hardware proportions.

Shared design decisions: every frame uses real hardware aspect ratios and sizes everything from the frame's own width (`cqw`, or one `--u` unit for the tablet and widgets), so a device looks the same at 160 px or 640 px; screen content is laid out at the device's logical width (1194 or 834, 412, 208 CSS px) and scaled, so real responsive pages render correctly inside; frames are decorative and add no focusable elements; the system UI pieces are real controls (buttons with `aria-pressed`, Radix sliders, a labelled password field); dates are fixed-locale and UTC so server and browser agree; and every animation has a reduced-motion path.

| Component | Competitor pattern studied | Ballmac improvement |
| --- | --- | --- |
| Tablet Frame | Magic UI and DaisyUI frames (phone and laptop only), Figma iPad kits | Landscape and portrait from one set of proportions (a single `--u` unit), brushed aluminum frame in silver or space black that follows the theme, long-edge camera, power and volume buttons, status bar with date, home indicator, scaled screen, image or video screen |
| Watch Frame | Static watch PNGs in kits | CSS case with digital crown and side button, curved glass highlight, strap that fades out above and below in sport (with holes), loop (woven lines) or leather (stitching), six strap colors from theme tokens, always-dark screen, scaled content at the 46 mm logical size |
| Android Frame | Magic UI Android, DaisyUI mockup-phone | Pixel-like satin frame in porcelain, obsidian or sage, centered punch-hole camera, Material status bar, gesture pill or three-button navigation, right-edge buttons, scaled screen at 412 px |
| Lock Screen | OS-clone login pages | Two real lock screens: macOS (live clock, avatar, password field that shakes and announces an alert when wrong, `password` and `onUnlock` for demos) and iOS (date, huge clock, notification slot, flashlight and camera, swipe up with a button for keyboard users); hydration-safe clock; animated unlock; fully controlled with `locked` |
| Control Center | shadcn toggle and slider (generic), OS-clone panels | Frosted panel of true toggle buttons (`aria-pressed`) with accent badges, clusters of rows like Wi-Fi and Bluetooth, pill sliders with the icon inside the track and a white thumb on Radix Slider (arrow keys, Home, End), and a Now Playing tile; controlled or uncontrolled |
| HUD | None in the major kits | The dark macOS square with a 16-segment bar and a slim capsule variant, springy in and out, timer restarts when the value changes, volume icon follows level and mute, polite status announcement while the visual is hidden from screen readers, and a `useTransientHud` hook |
| Widgets | Apple widget screenshots, dashboard cards | Weather (sky gradient per condition, hourly strip, daily range bars), calendar (UTC month grid with today circled, events with color bars), battery (rings turning red when low, charging bolt, list with bars on large); three sizes that scale with width; server components; each widget has a one-sentence accessible summary |

Accessibility notes: axe (serious and critical) is clean on every `/preview/*` page in light and dark, and `scripts/a11y-open-states.ts` scans batch B in its interacted states (wrong password with the alert, focused swipe button, toggled tiles with a moved slider, a visible HUD, the capsule HUD). Findings that shaped the final code: slider thumbs needed their own accessible name (Radix does not copy `aria-label` from the root), the first widget version resolved `cqw` against the wrong container and drew circles (the unit now lives on an inner surface element), and small widgets were too dense for 160 px so their layouts are tighter than the medium and large ones.
