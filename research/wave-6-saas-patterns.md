# Wave 6: SaaS patterns

Reviewed 2026-09-30. All 12 components are original Ballmac compositions over primitives already in the registry (Radix via `radix-ui`, Motion, and the Ballmac `popover`, `dropdown-menu` and `avatar`). No code was copied from Tailwind Plus, Aceternity, Magic UI Pro, or any other paid or unlicensed kit, so none carry a "Based on" header. Patterns were compared with the [shadcn catalog and blocks](https://ui.shadcn.com/blocks), [DaisyUI](https://daisyui.com/components/), [ReUI](https://reui.io/components/), [coss UI (Origin UI)](https://coss.com/ui), [Magic UI](https://magicui.design/docs/components), [Motion Primitives](https://motion-primitives.com/), [Aceternity](https://ui.aceternity.com/components) (visual ideas only), [Cult UI](https://www.cult-ui.com/docs), [Kibo UI](https://www.kibo-ui.com/components), [21st.dev](https://21st.dev/community/components), [Tailwind Plus](https://tailwindcss.com/plus/ui-blocks/application-ui) (application UI demos only) and real products (Stripe billing, Linear, Vercel, Notion and Intercom settings, onboarding and feedback surfaces), plus [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/).

Shared design decisions: status is always shown with an icon or word as well as color (colored chips keep foreground text for contrast, after axe flagged colored small text); money and dates use a fixed locale and UTC so the server and browser agree; every animation has a reduced-motion path; and each component ships the states a real product needs (empty, loading, warning, failed, done).

| Component | Competitor pattern studied | Ballmac improvement |
| --- | --- | --- |
| Onboarding Checklist | Linear and Notion getting-started cards; Intercom checklists | Progress ring plus segmented bar, expandable steps with a call to action, real checkbox semantics, auto-advance to the next step, and a celebration state with "review again" |
| Settings Panel | Stripe and Vercel settings pages; shadcn forms | Two-column sections that stack on phones, rows whose labels point at their controls, and a sticky save bar that slides in only when something changed, with a polite status announcement |
| Usage Meter | Vercel usage, Stripe metering, Figma limits | Three explicit states (icon and words), stacked segments with a legend, bar or ring, a warning tick on the track, and `role="meter"` with a readable value |
| Billing Card | Stripe customer portal; Linear billing | Gradient header with a large tabular price, status chip, next charge, seats meter, card chip, invoices with downloads, and dedicated failed-payment and trial states |
| Plan Selector | Stripe, Vercel and Linear pricing; Tailwind Plus pricing | Plans are real radio buttons (arrows, Space, form submit), sliding Monthly/Yearly switch with computed savings, prices that slide when the period changes, and a raised highlighted plan |
| Invite Members | Slack, Notion and Linear invite flows | Email chips from typing or pasting, per-chip problems in words (invalid, duplicate, existing), role picker, pending list with resend and revoke, and a sending state |
| Notification Center | Linear, GitHub and Intercom inboxes | Unread count in the button's accessible name, All and Unread views, day groups, per-row mark read and dismiss that appear on hover and focus, and an empty state |
| Feedback Widget | Vercel and Intercom feedback pills; Hotjar widgets | Five-face rating as a real radio group, topic chips, optional required comment, confirmation that closes itself |
| Changelog Feed | Linear, Vercel and Raycast changelogs | Sticky date and version column, change-type labels with icon and word, filter chips with counts, show-more for long releases, optional media |
| Cookie Consent | OneTrust-style banners; Vercel and Linear consent UIs | Reject and Accept have equal weight, a preferences view with locked required categories, non-modal dialog semantics, remembered choice |
| User Menu | Vercel, Linear and Notion account menus | Header card with plan badge and presence, link groups with shortcuts and badges, theme submenu with radio items, real links without nested interactive elements |
| Workspace Card | Slack, Notion and Linear workspace pickers | Cover and logo color generated from the name, member faces with overflow count, project and storage stats, a single stretched title link, actions menu and a loading skeleton |

Accessibility notes: axe (serious and critical) is clean on every `/preview/*` page in light and dark, and `scripts/a11y-open-states.ts` scans them in their interacted states (open step, changed settings, monthly billing, invalid chips, rated feedback, preferences view, open menus). Findings that shaped the final code: colored text on tinted chips failed contrast (fixed by keeping text foreground-colored), a definition list that held non-term children (replaced with plain elements), and examples that passed event handlers to client components needed `"use client"`. jsdom cannot complete height exit animations, so one row-removal assertion is covered in the browser instead.
