# Wave 10 batch A: macOS desktop pieces

Reviewed 2026-10-01. All nine items are original Ballmac code built on primitives already in the registry (Radix via `radix-ui` for context menu, toolbar and dialog, Motion, and the Ballmac `mac-window`). No code was copied from Aceternity, Tailwind Plus, any Pro kit or anything unlicensed, so none carry a "Based on" header. Patterns were compared with the [shadcn catalog](https://ui.shadcn.com/docs/components) (context menu, dialog, resizable), [Magic UI](https://magicui.design/docs/components) (Safari, iPhone and dock pieces), [macOS-style web clones](https://github.com/topics/macos-web) for window and Launchpad behavior (ideas only), [DaisyUI](https://daisyui.com/components/) mockup windows, and the real behavior of macOS 14 and 15: Finder, Launchpad, sheets, context menus, desktop icons and window management in Stage Manager.

Shared design decisions: every icon is drawn in SVG or CSS from theme tokens (no bitmaps, no third-party images), so it follows light, dark and any theme; the macOS accent blue is a local `--mac-accent` token set to a color that gives white text at least 4.5:1 contrast; everything is keyboard operable in the way macOS is (arrows, Return, Escape, Cmd-A, Cmd-Up); drag gestures always have a keyboard twin (Alt plus an arrow moves, Alt+Shift plus an arrow resizes); and every animation has a reduced-motion path.

| Component | Competitor pattern studied | Ballmac improvement |
| --- | --- | --- |
| Mac Icons | Magic UI and 21st.dev "Mac app icon" tiles, Lucide folders | Folder, file (with extension badge), drive and app icons with the macOS squircle ratio, gradient, inner highlight and drop shadow; eight tones from chart tokens; glyph scales with the icon; decorative by default so names live in text |
| Mac Context Menu | shadcn context menu (generic popover look), macOS menus | A true macOS menu: 22 px rows, blue highlight bar, left gutter for checks and icons, right-aligned key equivalents, destructive rows that turn white on highlight, submenus, radio groups; Radix keeps typeahead, arrows and focus return |
| Toolbar | shadcn toggle-group, macOS NSToolbar | Radix Toolbar (one Tab stop, arrows inside), labeled or icon-only buttons, segmented control, groups and separators, a search field that expands on focus, title and subtitle block; scrolls instead of clipping on phones |
| Sheet Dialog | shadcn dialog and sheet (centered or edge-attached to the page) | A macOS sheet: drops from the top of one window and dims only that window (via a `container`), with a Return-activated default button, destructive default, spring slide and a fade under reduced motion |
| Finder Window | Web "Finder" demos (static grids) | A working mini Finder: sidebar shortcuts, back and forward history, icon and list views, search, click/shift/cmd selection, a listbox with arrow, Return, Cmd-Up, Cmd-A and Escape, path bar; on phones the sidebar folds away and traffic lights move into the toolbar |
| File Browser | shadcn data-table, Vercel Blob and Dropbox lists | Breadcrumbs, search, sortable columns with `aria-sort`, select-all with an indeterminate state, bulk action bar, list and grid views, roving keyboard focus, file-type icons from the extension, UTC dates |
| Desktop Icons | Static icon grids in OS clones | Grid-snapped icons you drag, rubber-band selection, nearest-free-cell placement, a listbox keyboard model and Alt+arrow moves; labels get the macOS accent pill when selected |
| Launchpad | OS-clone app grids | Frosted overlay with search that filters as you type, pages measured from the container, page dots, wheel and key paging, arrows across pages, off-screen pages made inert, spring open and a blur-scale entrance |
| Window Manager | react-rnd, web OS demos | Real windows: drag by the title bar, 8 resize handles, raise on press, double-click to zoom, minimize into a tray, clamping to the desktop as it shrinks, controlled add and remove, and keyboard move, resize, close and minimize |

Accessibility notes: axe (serious and critical) is clean on every `/preview/*` page in light and dark, and `scripts/a11y-open-states.ts` scans batch A in its interacted states (open context menus, open sheets, selected and navigated Finder items, checked rows, selected desktop icons, open Launchpad on its second page, minimized and newly opened windows). Findings that shaped the final code: white text on the first accent blue measured below 4.5:1 (darkened), key-equivalent and section labels at 50 percent opacity failed contrast (use the muted token), the graphite tone turned white in dark mode because it mixed the foreground (now fixed grays), desktop labels broke mid-word (less padding), a new window wider than a phone desktop ran off the edge (windows are clamped), and the Finder sidebar took half of a 390 px screen (hidden on phones).
